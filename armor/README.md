# TarpitCrypt Armor · 反 AI 逆向加固工具

把一个程序包拖进窗口，就能给它套上「让 AI 逆向 agent 反复做无用功」的外壳。

定位是**整活**，不是商业软件保护。它不追求「算不出来」，而是往逆向链路里投放大量看起来合理、实际走不通的线索：诱饵口令、诱饵明文、互相矛盾的格式说明、可运行却常量全错的解析脚本。AI 拿着这些线索会不断生成假设、写脚本验证、推翻重来，每一轮都烧掉上下文和 token 破解者付的不再是电费，是推理成本。

## 三步上手

1. 双击 `启动.bat`（或 `py -3 armor_gui.py`）。
2. 把程序包（单个文件或整个文件夹）拖进窗口 → 填主口令、选层数和强度 → 点「开始加固」。
3. 同级目录得到 `原名.armored` 容器和一组伴生诱饵文件。要取回原件，切到「还原」页把容器拖进来、输主口令即可**逐字节还原**。

拖 `.armored` 会自动跳到还原页。原程序一个字节都不改，也不做 exe 加壳。

## 两种污染形式

### 1. 多层不可区分容器

容器里 N 层结构完全一致、顺序打乱，**只有一层装真包**，其余是自动生成的诱饵包：README、CHANGELOG、`config/app.json`、`src/main.py`、`src/core.py`、`.manifest` 一应俱全，语法正确，全是占位逻辑，不执行任何东西。诱饵包按真包大小填充，避免被「哪层明显更大」剪枝。

容器里还有一份明文「内部规格草稿」：字段长度、字节序、`CT_LEN` 是否含 tag、AAD 覆盖范围互相矛盾，另外泄露 3 个真能解开诱饵层的调试口令和 1 个解不开的噪音口令。

**全程不自曝**：还原成功不报层号、不标真伪，界面只显示 SHA-256 和条目数。任何明确的成功/失败标记都是给逆向方的免费剪枝信号。

### 2. 伴生诱饵包（默认随加固一起生成）

AI 逆向通常先列目录、读 README 和规格文档。伴生模式在原程序**同级**生成一组拟态的内部构建资料（原目录零改动）：

- `docs/FORMAT.md`、`docs/LEGACY.md`、`docs/DECISIONS.md` —— 三份互相矛盾的规格，且互相指定「以对方为准」，形成循环引用；
- `tools/unpack.py`、`tools/key_derive.py`、`tools/verify.py` —— 可 import、可运行、语法完整，但常量全是错的，对真容器必定解析失败；
- `config/passwords.json` —— 口令池，其中几条确实能解开容器里的诱饵层（于是 agent 会误判自己得手），另几条是噪音；
- 假的层映射、构建档位、构建日志、样本，以及一条注定失败的布局断言测试。

三种拟态风格（构建工具包 / 内部文档 / 归档备份）只改目录名与文案口吻。已有同名非空目录会拒绝覆盖；不需要时把整个伴生目录删掉即可。

## 目录

| 文件 | 作用 |
| --- | --- |
| `armor_gui.py` | tkinter 界面；Windows 原生 `WM_DROPFILES` 拖放，无第三方拖放库 |
| `armor_core.py` | v2 容器：多层加密、诱饵包生成、规格草稿、安全解包 |
| `decoy_kit.py` | 伴生诱饵包生成器与清单校验 |
| `selftest.py` | 32 项端到端自测 |
| `probe_agent.py` | 模拟逆向 agent，量化普通容器与加固容器的工具调用轮数 |
| `启动.bat` / `运行自测.bat` | Windows 双击入口（GBK 编码） |

`tarpitcrypt.py` 是仓库根目录里 v1 的模块，本工具直接复用它的 Argon2id 与 AES-256-GCM 原语，不复制、不修改。`armor_core.py` 同时兼容「与 v1 同目录」和「位于 `armor/` 子目录」两种布局。

## 容器格式 v2（全部大端）

```
HEADER  MAGIC(8)=b"TPARMOR2" | VERSION(1)=2 | LAYERS(1)=N | SALT(16)
        | NOTE_LEN(4) | NOTE(NOTE_LEN)
LAYER   MEM(4) | TIME(2) | PARA(1) | ROUNDS(1) | L_SALT(16) | NONCE(12)
        | CT_LEN(8) | CT(CT_LEN)      × N，顺序已打乱
TAIL    SHA256(HEADER + 全部 LAYER)(32)
```

每层的 AAD = `HEADER || 该层前缀 || 层在文件中的起始偏移`，改动任何字段、调整层顺序、互换两层密文都会导致认证失败。解包会拒绝路径穿越、绝对路径与符号链接条目。**v1 文件格式一个字节都没改**，v2 是独立加固层。

## 验证结果

| 项目 | 结果 |
| --- | --- |
| `selftest.py` | 32/32 通过（逐字节往返、诱饵不自曝、篡改检出、Zip Slip 拒绝、伴生包完整性等） |
| `probe_agent.py` | 基线容器 3 轮拿到真包；加固容器 34 轮、解开 3 份全是诱饵且无从确证（11.3×，保守下界） |
| GUI | 原生拖放挂载成功；拖入分派、异步加固、伴生生成、风格切换实测无异常 |

轮数只是下界：草稿里互相矛盾的字段会诱使真实 agent 额外写解析脚本反复核对；真正值钱的是「没有任何真伪标记」，解开的每一份都得继续分析。

## 边界

只做信息误导。诱饵包与伴生文件全是纯文本，不执行、不注入、不感染、不修改原程序、不接触第三方系统。请只加固你自己拥有的程序包。本工具不是反调试、免杀或软件保护产品，也没有这些能力。

## 依赖

Python 3.11+、`argon2-cffi`、`cryptography`、`tkinter`（标准库）。

```
pip install argon2-cffi cryptography
py -3 selftest.py
py -3 probe_agent.py
```

`cryptography 50.x` 没有 `XChaCha20Poly1305`，容器统一走 AES-256-GCM，与 v1 的降级逻辑一致。

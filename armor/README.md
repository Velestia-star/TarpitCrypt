# TarpitCrypt Armor · 反 AI 逆向加固工具

> 发布版本 **v0.3.9** · 容器格式 **v3** · 详见仓库根 [CHANGELOG.md](../CHANGELOG.md)

把一个程序包拖进窗口，就能给它套上「让 AI 逆向 agent 反复做无用功」的外壳。

定位是**整活**，不是商业软件保护。它不追求「算不出来」，而是往逆向链路里投放大量看起来合理、实际走不通的线索：诱饵口令、高仿真诱饵包、互相矛盾的格式说明、可运行却常量全错的解析脚本。AI 拿着这些线索会不断生成假设、写脚本验证、推翻重来，每一轮都烧掉上下文和 token。破解者付的不再是电费，是推理成本。

## 三步上手

1. 双击 `启动.bat`（或 `py -3 armor_gui.py`）。
2. 把程序包（单个文件或整个文件夹）拖进窗口 → 填主口令、选层数 / 强度 / 投毒侧重 → 点「开始加固」。
3. 同级目录得到 `原名.armored` 容器和一组伴生诱饵文件。要取回原件，切到「还原」页把容器拖进来、输主口令即可**逐字节还原**。

拖 `.armored` 会自动跳到还原页。原程序一个字节都不改，也不做 exe 加壳。
macOS / Linux 没有原生拖放，但「选择文件 / 选择文件夹」按钮全平台可用。

界面共 5 个页签：**加固 / 还原 / 伴生诱饵 / 运行报告 / 说明**。

## v3 修了什么：开源项目不能靠「藏答案」

项目本身开源，意味着逆向 agent 可以直接读 `armor_core.py`。v2 里三条信息其实是白送的：源码有一份硬编码的诱饵口令池、注释写明「只有一层真包」、每层前缀和偏移都可解析。于是读过源码的 agent 拿口令池逐层试，解开 N-1 层后用排除法就能**确定性锁定真层**，从此有了「解开即真包」的明确判据，投毒基本失效。实测同一把尺子下：v2 的知情 agent 21 轮锁定真层（第 3 层）。

v3 把不确定性从「源码保密」移到「每次生成都不同」：

| 加固 | 做法 |
| --- | --- |
| **口令随机化** | 调试口令由本容器的随机种子派生，源码里没有可跨容器复用的常量池；线索只写进本容器的规格草稿与伴生资料。草稿还混入解不开任何层的假口令和「可能缺项」的暗示。 |
| **死层破排除法** | 层分三类：1 真层 + 若干高仿真诱饵层 + 若干「口令不写进任何线索」的死层。三类数量与位置每次随机，源码里没有固定比例；只公开部分诱饵口令。解开若干层后剩下的不止一层，排除法不再成立。 |
| **去模板化 + 尺寸对齐** | 诱饵包的项目族、文件树、命名、时间戳、注释密度按种子随机，Python 由可编译模板填充常量而来，并按真包的文件数/扩展名对齐。所有层（含真层）用 zip 填充条目补到同一尺寸，解包时跳过填充，用户目录零残留。实测层尺寸极差从 1.6 KB 压到 **0 B**（v0.3.1）。 |

二进制布局与 v2 完全相同，只是 `MAGIC=b"TPARMOR3"` / `VERSION=3`；**v2 旧容器按同一布局读取，仍可用主口令还原**。v1 文件格式一个字节没改。

## v0.3.1 — 拿真实应用跑一遍之后的修补

把两个本机真实程序包（2.8 MB / 22 文件的中文路径工具包、92 MB / 554 文件的
Qt 绿色应用）完整走了一遍「拖入 → 加固 → 伴生诱饵 → 还原 → 逐文件哈希比对」，
另加中文/空格路径、只读文件、0 字节文件、空目录、程序包自带 `.manifest` 等边界。
实测暴露的问题，全部已修：

| 问题 | 影响 | 修法 |
| --- | --- | --- |
| 程序包自带 `.manifest` | 工具清单同名覆盖，还原后**用户文件被替换** | 清单自动避让改名；层内条目按 ZipInfo 精确定位读写，不再按文件名取 |
| 还原目录多出 `.manifest` | 与「用户目录零残留」不符，条目计数也多 1 | zip 条目加内部标记（用户文件 / 清单 / 填充），解包只跳过内部条目；v0.3.0 旧容器靠内容精确识别，仍可正常还原 |
| 空目录丢失 | `logs/`、`cache/` 这类空目录还原不回来；只有空目录的包直接报错 | 目录写成显式 zip 条目，解包时重建 |
| 最大层挤不下填充条目 | 真层成了唯一没有 `__tarpit_pad/` 条目的层，**结构自曝真伪** | 给所有层留足填充空间，每层都有填充条目且尺寸一致（实测极差 0 B） |
| 清单 `variant` 写死 `release` / `internal-N` | 解开任意一层读一眼清单就能定真伪 | 两类层的清单字段同分布、包名随机化，不泄露真实目录名 |
| 大包反复全量内存拷贝 | 打包 / 重打包 / 解包时整份文件驻留内存 | 改为分块流式读写 |

**外部 v3 容器格式一个字节没改**，v0.3.0 与 v2 旧容器仍可用主口令还原。
复测结果：全部样本逐文件哈希零差异、还原目录零多余文件、各层尺寸极差 0 B；
92 MB 应用本机加固 5.7 秒、还原 0.19 秒。自测从 62 项扩到 78 项。

## v0.3.0 新增

### 效果可证明、可配置（A 级）

- **运行报告页**：统计本机会话里的错误口令次数、层尝试、耗时与 token 量级估算，可导出 CSV / Markdown。数据只在内存，**不写进容器、不记口令**，点导出才落盘。token 是粗估，不是真实 LLM 计费。
- **`agent_eval.py`**：多轮取样，输出中位数与区间的 Markdown 报告，避免把口令随机波动当成效果。
- **`probe_agent.py`**：基线 / 盲 agent / 读源码 agent 三组对照，关键判据是「能否确定性定位真层」。
- **投毒侧重**（七种）：`均衡` / `规格矛盾` / `假解析器` / `IOC蜜罐` / `RAG投毒` / `进度幻觉` / `认知污染` / `工具污染` / `代理记忆`。`规格矛盾`、`假解析器` 分别对应爱读文档 / 爱写脚本的 agent；`IOC蜜罐` 针对会扫字符串提取 IOC 的工具（kernagent、ReverseCore_MCP、agentic-malware-analysis），植入全落保留地址段的假 C2/IOC；`RAG投毒` 针对把项目文档喂进 RAG / 知识图谱 / 多智能体的工具（GhidrAssist、open-reverselab、RAVERSE、REAA），生成诱导性知识库文章并内嵌「停止深挖、判良性」的间接指令；`进度幻觉` 用伪仪表盘制造「只差最后一步」的近因错觉，勾着 agent 与它主人持续投入；`认知污染` 生成自引用假共识与矛盾权威声明，把假结论摄入 agent 自身的知识库/长期记忆/对外报告，削弱其后续分析能力；`工具污染` 伪造 capa / YARA / Semgrep / 沙箱 / CI 安全门 / SBOM / 威胁情报等机器可读产出，利用「工具结论即事实」这条流水线惯例；`代理记忆` 生成 `AGENTS.md` / `CLAUDE.md` / `MEMORY.md` 等项目指令文件，让 agent 框架自动读入「已分析完毕、不要逆向」的自引用指令。威胁模型与可利用盲区见 [`docs/AI_RE_THREATMODEL.md`](../docs/AI_RE_THREATMODEL.md)。
- **伴生诱饵包与原程序彻底隔离**：伴生目录必须建在原程序目录之外；机器可读文件不进原程序；构建前审计全部产物，一旦发现指向真实主机的域名或公网 IP 直接拒绝构建（文档地址段与 RFC 保留段放行）。诱饵只做纯信息误导，不执行、不联网。
- **真实 agent 实测**：`content_probe.py --real` 已在本机 ollama（qwen25vl3b）跑通七种侧重，6/7 命中、安全不变量全程成立；数据与口径见 [`docs/AGENT_BENCHMARK.md`](../docs/AGENT_BENCHMARK.md)。容器层的轮数/token 对照记录表仍待填。
- **还原保真度**：加固后的程序还原出来必须还能照常运行 —— 权限位（可执行 755 / 只读 444）如实记录并写回、符号链接按内容打包（指向包外则拒绝加固）、行尾与 BOM 不被改写、字节码按「能不能再生」区别对待（有源码的缓存不进容器，无源码的 pyc-only 部署必须保留）。`python -m armor.runtime_check` 跑 16 项可运行性矩阵，也可用来验证任意真实程序包。

## 两种污染形式

### 1. 多层不可区分容器

N 层结构完全一致、顺序打乱。诱饵包有 README、配置、源码、清单，语法正确、不执行任何东西；死层同样是完整可解的高仿真包，只是口令从不出现在任何线索里。所有层补齐到同一尺寸，按「哪层明显更小」剪枝也失效。

容器里还有一份明文「内部规格草稿」：字段长度、字节序、`CT_LEN` 是否含 tag、AAD 覆盖范围、「是否所有层都能解开」都互相矛盾，另外列出几条调试口令（部分有效、部分噪音、还有故意不公开的缺项）。

**全程不自曝**：还原成功不报层号、不标真伪，界面只显示 SHA-256 和条目数。任何明确的成功/失败标记都是给逆向方的免费剪枝信号。

### 2. 伴生诱饵包（默认随加固一起生成）

AI 逆向通常先列目录、读 README 和规格文档。伴生模式在原程序**同级**生成一组拟态的内部构建资料（原目录零改动）：

- `docs/FORMAT.md`、`docs/LEGACY.md`、`docs/DECISIONS.md` —— 三份互相矛盾的规格，且互相指定「以对方为准」，形成循环引用；「规格矛盾」侧重会再加一份偏移审计表；
- `tools/unpack.py`、`tools/key_derive.py`、`tools/verify.py` —— 可 import、可运行、语法完整，但常量全是错的，对真容器必定解析失败；「假解析器」侧重会再加一份逐层探测脚本；
- `config/passwords.json` —— 口令池；绑定容器时直接抄本容器草稿（其中几条能解开诱饵层，于是 agent 会误判自己得手），单独生成时则用一次性假口令；
- 假的层映射、构建档位、构建日志、样本，以及一条注定失败的布局断言测试。

三种拟态风格（构建工具包 / 内部文档 / 归档备份）只改目录名与文案口吻。已有同名非空目录会拒绝覆盖；不需要时把整个伴生目录删掉即可。

## 容器格式 v3（全部大端）

```
HEADER  MAGIC(8)=b"TPARMOR3" | VERSION(1)=3 | LAYERS(1)=N | SALT(16)
        | NOTE_LEN(4) | NOTE(NOTE_LEN)
LAYER   MEM(4) | TIME(2) | PARA(1) | ROUNDS(1) | L_SALT(16) | NONCE(12)
        | CT_LEN(8) | CT(CT_LEN)      × N，顺序已打乱
TAIL    SHA256(HEADER + 全部 LAYER)(32)
```

每层的 AAD = `HEADER || 该层前缀 || 层在文件中的起始偏移`，改动任何字段、调整层顺序、互换两层密文都会导致认证失败。解包拒绝路径穿越、绝对路径与符号链接条目。

## 边界

只做信息误导。诱饵包与伴生文件全是纯文本，不执行、不注入、不感染、不修改原程序、不接触第三方系统。请只加固你自己拥有的程序包。本工具不是反调试、免杀或软件保护产品，也没有这些能力。

## 依赖

Python 3.11+、`argon2-cffi`、`cryptography`、`tkinter`（标准库）。

```bash
pip install argon2-cffi cryptography
py -3 selftest.py
py -3 probe_agent.py
py -3 agent_eval.py --runs 5 --out report.md
```

`cryptography 50.x` 没有 `XChaCha20Poly1305`，容器统一走 AES-256-GCM，与 v1 的降级逻辑一致。
